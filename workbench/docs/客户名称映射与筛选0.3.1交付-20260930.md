# UL 随行 0.3.1：客户名称映射与筛选

交付日期：2026-09-30  
Android：`0.3.1-dev`，versionCode 10  
N150 服务：`1.4.1`，Docker 镜像 `ul-workbench:0.4.1`

## 业务口径

- WMS 订单字段 `receiveraddress` 作为 UL 随行的客户／公司名称。
- 后端同时写入订单的 `customer_name` 和兼容字段 `buyer`，并标记来源 `wms_receiveraddress`。
- `receiveraddress` 为空时保持空值，不使用收件人姓名、手机号、账号或其他字段推测。
- WMS 本地日期缓存只新增保留 `receiveraddress`，其他收件人信息仍不持久化。
- 0.3.1 以前快照中可能存在的店铺账号类 `buyer` 值不会进入客户候选项，也不会在订单中冒充客户名。

## 查询与界面

- `GET /api/v2/orders` 接受 `customer`精确筛选参数，可与摘要、物流分类、打印状态、订货日期、交期和排序组合使用。
- 响应增加 `customer_options`、`customer_count` 和当前 `customer`。候选项从当前其他筛选范围中的非空客户生成。
- Android 订单筛选面板新增“全部客户／具体客户”下拉选择，顶部筛选摘要显示已选客户。“全部打印”的查询快照也携带客户条件。

## 生效方式

后端部署后不会自动重读 ERP。待 `receiveraddress` 改成公司名称后，在 App 中手动点击“更新订单”：

1. N150 重读未发货订单及 WMS 明细。
2. 新的 `receiveraddress` 进入已发布 SQLite 订单快照。
3. 再次打开订单筛选面板时，客户下拉显示当前未发货订单中实际出现的公司名称。

在手动更新前，现有已发布缓存可继续查询，客户下拉可能为空，这不表示 API 读取失败。
