# UL随行 0.4.11-dev 发布验证

2026-10-07 发布。Android 0.4.11-dev / versionCode 24；兼容后端 `ul-workbench:0.5.17-codex-summary`。

## 实际交付

销售通过自己的 App 账号提交文字、照片、Excel、PDF，N150 Codex 使用 NAS 原六份匹配规则及只读历史参考，分析订单、核对编码、询问缺项，生成待确认草稿。未匹配商品生成建议；管理员确认冻结新编码方案，实际商品、SKU、支单位及江苏优螺库存验证通过后才能使用。确认草稿后校验 XLS，再进入统一网页队列上传。

摘要与现有 App 字段对应：`客户订单号#项目号#客户行号#料号/图号#原品名#原标准规格#等级#表面#数量#ERP编码#交期=YYYY-MM-DD`。每条客户明细生成独立 ERP 单据，同一个文件批量上传；该行 G“摘要”和 Y“明细备注”相同，原行号如 `010/A10`、客户料号及各自交期保留，不共用首行摘要。成功后 App 显示单据数量、首条单号及完整单号列表。

原字段包含 `#` 时阻止导入并保留输入。App 历史解析仍将下划线显示为空格，原附件及 XLS 保留原文字，暂不宣称所有特殊符号在手机显示中逐字相同。原 v1 冻结订单保持原单号、表格及回执，不重新生成或补传。

依用户选择，不做 ERP 销售订单回查；只有网页确认完整文件导入才算成功。部分、超时或未知结果进入待核对，不自动重传。新品创建回查独立保留。采购及付款能力不因本次销售录单发布自动开放。
