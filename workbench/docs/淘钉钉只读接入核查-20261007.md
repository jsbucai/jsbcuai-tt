# 淘钉钉只读接入核查

日期：2026-10-07。N150 使用隔离的临时官方 MCP 会话，以用户提供的账号完成只读核查。未保存密码或 Token 到 N150 文件、环境变量、浏览器配置、项目或 NAS；未加购、下单、付款、取消订单或修改任何商品。登录会话不是生产只读授权：本次密码登录返回 `shop:read`、`cart:write`、`quote:submit`，应优先申请仅 `shop:read` 的授权。两次临时会话显式退出，另两次进程结束但未显式退出；本地已无可复用 Token，服务端会话是否过期仍由平台管理。

官方能力说明：[淘钉钉 MCP 文档](https://www.taodingding.com/readme/)。公开接口支持账号、商品、包装、订单查询及购物车写入；未提供下单或付款 MCP 方法，文档当前明确让客户在官网购物车人工核对并结算支付。自动交易若仍要推进，须先向平台确认可用的正式接口或网页自动化范围，再对具体下单、付款和回查流程单独验收；不能把“购物车成功”当成“下单付款成功”。

## 实测结果

| 项目 | 结果 | 使用约束 |
|---|---|---|
| 账号身份 | 临时登录后 `get_current_user` 与输入账号一致 | 正式执行前每次复核身份；不得复用管家婆凭据 |
| 历史订单 | `list_orders` 每页 100 条，共 78 页，响应汇总 `total=7,745`；实际读取与 `(id,type,number)` 去重后均为 7,745 | 分页完整性只对本次查询时间成立；后续增量需记录时间窗口和翻页去重 |
| 合并支付订单 | 首页 100 行有 30 行为集合，包含 68 个子单；集合顶层 `id/type/paystate` 为空 | 必须展开 `orderList`，逐子单绑定平台订单，不能把顶层空状态当成未付款 |
| 订单详情 | 一笔既有普通订单的 `id/type/number` 及 `summary.paystate/orderstate` 与列表一致，商品明细可读 | 只验证了既有订单；提交后唯一关联、金额和支付结果仍未验收 |
| 商品包装 | 一个已知平台 SKU 有三个 `optionId`，`baseUnit=千支`；箱、盒、散支的 `quantityPerPackage` 分别为 0.12、0.03、0.001，即 120、30、1 支 | 必须按实时 `optionId + baseUnit + quantityPerPackage` 换算为支，再比对 WMS 每支价格；不得直接比较每盒标价 |

正式采购适配器仍缺少：精确身份与包装选项的实时复核、含税和运费后的应付金额、平台支持的创建未付款订单方式、唯一订单绑定、支付状态和实付金额回查、超时恢复、ERP 补录及对账。上述任一证据缺失时，只能保持候选或待人工核对，不能自动付款。
