# 电脑录单工作台 0.5.23

入口 `/sales`，首版仅现有管理员本人登录。与 App、微信共用会话、原附件、客户负责人、商品目录和草稿。

## 使用

选择客户和本次经手人（李瑄／刘锋），发送文字、图片、Excel 或 PDF。页面显示排队、资料分析、编码匹配及草稿核对进度，可停止后补充。采用草稿后修改表格，查看原文与候选；确认摘要和商品差异后保存。校验并确认冻结当前版本，再点击“确认录入 ERP”。

客户选择读取 `erp.btype.list` 全部分页资料，不再局限于已设置固定销售的名单。每页50项，支持名称、单位编码、拼音搜索，并显示最后成功同步时间。目录按 ERP 单位身份保存；停用和删除项不用于新建；同名项分别显示并暂停新建。未指定固定销售时，在网页选择李瑄或刘锋，点击“保存固定销售”后即可开始录单；保存复用 App 同一归属表及未完成任务同步逻辑，整批原子校验。已有负责人不通过此入口转移；本次经手人与固定归属分开保存。新会话冻结选择时的 ERP 单位ID，提交前再次验证。

0.5.23.2 增加对话管理：打开对话后右上角“删除对话”，确认后从正常列表移除；左侧“已移除”可查看、恢复。原消息、附件、草稿和业务记录不做物理删除。正在整理的 Codex 任务同步取消，迟到结果不能回写；正在录单或创建商品的任务须等结果后再移除。已有 ERP 尝试或已提交的对话使用“收起对话”，原回执继续保留。旧客户端不能继续修改已移除的会话；恢复后重新校验草稿版本。

客户目录后台每小时更新（北京时间07:30至19:00内），手动“更新客户名录”可随时排队。完整分页核对后一次发布；失败、重复身份或异常空目录保留上次正确数据。目录不含联系人、电话、银行资料。客户资料自动更新不改订单中的客户名称，也不改变负责人。

摘要使用既有十段格式，末尾 `#交期=YYYY-MM-DD`；不再写附加说明。仓库江苏优螺，制单人罗健树，单位支，税率13%。默认客户报价含税，除1.13后未税单价三位、行金额两位。一个原始明细一个独立ERP单号，重复SKU不合并。

ERP API 仅创建未审核销售订单。API 回执有有效单据标识后显示已录入；之后由本人审核，审核后进入未交清单。查不到未交不能触发重传。不启用任何 N150 网页自动化。

2026-10-20 样单 `UT02EE58ACAD4D57CE76`：备用零售客户、LS3073、3支、含税报价2元、合计6元、交期2026-10-23，经手人李瑄、制单人罗健树。API返回有效单据标识，用户确认全部正确且创建时未审核。前一张1.25元样单被低于进价规则拒绝，没有自动绕过。

## 保留与恢复

聊天、附件、队列与确认模型存于原业务数据库，未保存表格和未发送文字留在当前电脑当前账号。网络结果不确定时保留原操作标识，手动“恢复原操作”使用同一请求。提交中断后冻结未知单据，不重复发送；部分成功明细保留真实回执，剩余暂停。

库存数量、物流或照片更新不使整理任务失效。商品身份、规格、单位、客户归属及草稿本身变化仍要求核对。新增编码仅经管理员确认且回查唯一真实身份后使用。

技能优化为版本化补充规则：输入问题样本、预期编码及需否补充，运行基准／候选对照，通过后人工发布，可恢复上一版。样本测试是语言理解与字段识别对照，不冒充全业务验收。新任务固定规则版本；模型不能更改税价、权限或提交保护。

## 运行

静态前端在 Python 服务内提供，N150 无 Node 开发服务器。Codex App Server 仅私有 stdio，工具与网络检索关闭，不提供公开执行端口，不给模型 ERP 密钥。Codex、新编码和 API 提交沿用单重任务锁；新增 API worker 192MB / 50%CPU上限。SSE最多两个连接并周期释放；技术进度事件保留最近约20000条，原业务记录完整保留。

部署：NAS一致性加密备份 → 基于当前镜像叠加兼容后端和静态资源 → 更新独立worker → 配置验证过的API范围 → 健康、登录边界及真实只读Codex草稿检查。无需更新APK。

回退：停 `ul-sales-api.timer`，改回之前镜像，移除 App Server worker环境覆盖并恢复程序文件。不覆盖数据库，不删除新草稿、API尝试、已创建订单、打印或人工记录。
