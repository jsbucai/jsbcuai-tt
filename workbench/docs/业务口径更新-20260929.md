# UL 随行业务口径更新（2026-09-29）

用户确认以下业务事实，后续实现与测试以此为准：

- 订单摘要末尾使用 `#交期=YYYY-MM-DD`；该日期同时用于物流单号 `@MM/DD#完整订单号` 和逐明细催货判断。
- 奇门 `sell_count` 与匹配 WMS 明细数量均表示剩余未发数量。两者同时存在时应核对一致，不一致时阻止受影响库存分配范围。
- 催货仅依据交期规则，不再把采购下单日期或供应商作为输入。精确边界仍以原电脑当前正式脚本的回执为准。
- 采购未到总量为 `physical_qty - saleable_qty`，包含采购订单数量和改制单数量。
- 到货与库存变化优先读取单据中心：进货入库 34、进货退货 6、进货换货 143；报损 9、报溢 14、生产组装 16 作为库存变化的后续补充范围。
- 物流分类只处理仓库 `29871293290508390`（08390）。
- 首次 N150 分类不能清空入库账本。须导入旧电脑同一时点的事件余额、订单分配关系和身份映射并核对后启用。

性能方向采用分层缓存：商品、SKU、仓库等主数据保存在 N150；日常更新只读取订单、库存及自上次水位后的单据变化，然后重新计算受影响的库存分配范围。定期全量校验用于发现漏页、历史修正和删除，不把增量结果直接当成完整性证明。
