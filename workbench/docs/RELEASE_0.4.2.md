# UL 随行 0.4.2-dev：完整任务清单与同品派工

任务首页默认显示本人全部未完成事项。列表分批读取 50 项，滚动自动继续加载；50 是网络分页大小，不是任务或可见数量上限。筛选内可切换“本岗位全部”，查看同岗位其他负责人和未分配工作，处理及打印仍校验本人负责权限。

销售按客户整单查看，采购按商品查看需采购和待到货，包装按商品与货位集中查看跨客户订单。正常等待事项保留可见并后置。日期、负责人等条件放在筛选面板；顶部保留简短岗位、时间和操作入口。记录处理使用点选结果和日历，多项相同结果可以一次提交。

包装取消原每人 10 条的派工限制。同一岗位内，相同账套、仓库、商品、SKU 和单位尽量由同一人执行；兼岗负荷合并计算。多商品系统订单作为组合包装完整派给一人。已有操作、打印、未知出纸、已包装及人工交接记录的任务保留负责人，不在升级时重新分配。

同品集中备货仍按客户系统订单分别装包贴标。打印中及未知出纸保持独占；点击已打印不会自动标为已包装，已包装等待 ERP 发货确认。全选由服务器固定完整范围，不只选择手机已经加载的第一页。大批量标签按原打印容量顺序分段，出纸未知时停止后续发送。

本版只使用已经发布到 N150 的缓存计算工作安排。业务数据仍由管理员点击“更新订单”同步。任务页升级不会自动读取 ERP、写物流、生成采购单或确认发货。缓存过日时保留真实数据时间，提醒更新；升级重组既有任务负责人不会改变 FIFO 分配。

## 安装与使用

1. 覆盖安装 `UL-Workbench-0.4.2-dev.apk`，版本号 15，应用 ID 和开发签名保持不变。无需卸载原 App，会话、设备 ID 和手机报损报溢草稿保留。
2. 员工打开任务页选择自己的岗位，直接滚动查看全部工作。筛选面板可切换本人／本岗位、交期和负责人。
3. 销售或采购多选事项后记录共同处理结果；需要不同承诺日期的事项分别选择。跟进记录不等于业务已解决。
4. 包装展开商品后选择本人的系统订单执行。选择“全部”前核对服务器返回的总数量；其他人的订单只读。
5. “今日记录”查看自己的处理、包装和业务确认记录。管理员在人员管理中调整岗位和在岗安排，原包装限额不再控制新版派工。

## 数据、备份与回退

后端镜像 `ul-workbench:0.5.3`，服务版本 `1.5.2`。SQLite 从 v7 增量升级到 v8，保存商品负责人、固定选择范围、批量请求幂等结果和结构化跟进信息；原任务 ID、打印账本、人员、会话和历史均保留。

部署前和部署后执行现有 NAS 加密一致性备份。恢复到新目录，保留恢复暂停状态，先核对备份后发生的包装及打印，不盲目重放未知操作。仅回退程序时可保留新增表；需要恢复数据库时，必须停服并保留当前数据库，不能用升级前备份覆盖升级后业务记录。

验证结果和安装包哈希记录在本次 NAS 交付目录的验证报告。自动化验证不替代 A300E 实际出纸、手机扫码枪和两名员工现场包装确认。
