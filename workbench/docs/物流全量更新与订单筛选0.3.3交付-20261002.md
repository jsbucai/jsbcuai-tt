## 关键改造

### 写入策略

正式模式使用独立显式范围：

```dotenv
UL_LOGISTICS_WRITE_ENABLED=1
UL_LOGISTICS_WRITE_SCOPE=all
UL_LOGISTICS_WRITE_MAX_PER_JOB=0
UL_LOGISTICS_WRITE_ALLOWLIST=
```

`all` 与非零上限或非空白名单同时存在时，服务直接拒绝启动，避免看似全量、实际仍被截断。策略在任务入队时冻结；超时或断连继续记为 `unknown`，不自动重发。

写入进度每 10 笔持久化一次。每笔请求本身仍先写入 `freight_attempts`，只是不再每笔重建已累积的整个请求列表，避免几千张订单时产生平方级数据库写入。

### 库存件查询

原报错根因是：任一订单计算阻断都会把整份 API 快照标记为“无物流公司列”。现改为逐订单判断：已计算行可继续筛选，阻断行不会混入库存结果。同时保留对真正缺失该列的旧 Excel 快照保护。

后端和整单打印查询同步支持：`异常`、`需采购`、`待到货`、`催货`、`来货件`及五类库存件。

### Android 界面

- 顶部分类条可横向滑动，选中库存细分后显示如“库存 LM”。
- 筛选弹窗重新使用红、白、黑规范，在 320dp 小屏上保持“取消／应用筛选”操作区可见。
- 打开筛选或库存分类弹窗时暂停扫码，避免外接扫码枪误触发。
- 日期使用 Material 3 日历，关闭文本输入模式。

## 安装和日常使用

APK 为 `UL-Workbench-0.3.3-dev.apk`。它使用同一 `applicationId` 和原签名，可直接覆盖安装；不要卸载旧版，以保留登录状态和手机内报损报溢草稿。

以后点“更新订单”时，N150 仍会读取最新业务数据并重算分类，但 ERP 只接收相对 2380 张成功缓存发生变化的订单。新订单、公司改变或交期导致单号改变时才会新增 ERP 写入。
