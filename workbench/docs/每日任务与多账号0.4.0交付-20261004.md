# UL 随行 0.4.0：每日任务与多账号

日期：2026-10-04

## 功能范围

本版在原 Android、N150 Flask 和 SQLite 架构中增加“任务”首页，不引入新的数据库服务或后台定时业务同步。

- 四个岗位：销售、采购、库存件包装、来货件包装。
- 每人独立账号，可同时配置多个岗位；管理员账号继续兼容原来的仅密码登录。
- 每次手动“更新订单”成功发布数据后，N150 使用同一数据版本重建任务投影。
- 销售和采购事项持续保留负责人、处理记录与下次跟进日期。
- 包装按整单分配，每名员工两个包装岗位合计默认最多 3 单。
- 打印、已包装待发货和 ERP 已确认发货是三个独立状态。
- 自动派工默认关闭。首次上线先查看任务预览，再建立员工、设置在岗状态并由管理员开启。

报损报溢仍走原电脑局域网服务。订单、库存、图片、台账、打印协调和每日任务继续由 N150 提供。

## 任务来源与口径

任务只从当前已发布的订单、物流分类计算、库存分配、生命周期和打印状态生成，不读取 ERP 物流公司字段作为唯一依据。

| 岗位 | 主要任务 | 关闭依据 |
| --- | --- | --- |
| 销售 | 逾期、催货、交期或客户资料缺失、已包装待发货 | 新一轮同步确认条件解除，或 ERP 确认发货 |
| 采购 | 采购缺口、催货供货、来货滞留缺项、结存资料核查、库存计算资料核查 | 新一轮同步确认条件解除 |
| 库存件包装 | LS、LD、LM、DQ、QT 中满足整单包装条件的订单 | ERP 连续确认已发货；员工“已包装”只进入待发货 |
| 来货件包装 | 已齐货来货件和已齐货滞留异常；未齐货异常显示只读等待事项 | ERP 连续确认已发货；缺项异常关联采购处理，齐货后才进入包装 |

采购任务按账套、08390 仓库、商品、SKU 和基本单位的稳定身份聚合。界面列出关联订单及缺口；供应商、采购单和到货承诺由员工填写，不从缺失的 API 关系中猜测。

未齐货的“异常”订单会在来货件包装岗位显示只读等待卡，并列出缺项及关联采购事项。它不分配包装负责人、不占每人 3 单额度，也不能开始包装、打印或确认完成；后续同步确认齐货后，系统关闭等待卡并生成或恢复正常整单包装任务。

“已完成订单需结存”不进入包装。采购负责采购入库、成本或结存资料核查；需要售价确认的处理内容可由管理员转交销售。

## 状态与统计

销售、采购处理动作支持：开始处理、记录进展、等待协同、提交解决结果。记录进展、等待协同和提交结果必须填写说明；未解决事项必须设置下一次跟进日期，默认下一个工作日。

包装流程为：

```text
待包装 → 包装中 → 已包装待发货 → ERP 已确认发货
```

- “已打印”不等于“已包装”。
- 出纸未知会阻止确认已包装，必须先核对并恢复打印状态。
- 已包装后生成销售“待确认发货”事项。
- ERP 只出现一次 500／600、订单暂时消失或查询失败时，不计业务完成。
- ERP 没有可靠实际发货时间时，统计名称为“今日确认完成”。

任务页分别显示今日待办、处理中、待协同、今日处理动作和今日业务完成。条件自然解除、订单取消、管理员转交和员工处理分别记录，不把系统自动关闭算成员工完成。

## 自动派工

新事项按以下顺序确定负责人：

1. 管理员配置的销售客户规则或采购商品规则。
2. 同一客户或商品最近仍有效的负责人。
3. 同岗位当日在岗人员中当前事项最少者；数量相同轮流分配。

包装还受个人包装上限约束，默认两个包装岗位合计 3 单。优先级为急单、逾期或当日交期、来货滞留异常、其他交期，并在同级中参考货位顺序。排队只安排工作，不改动现有 FIFO 库存和来货分配。

员工离岗、停用或岗位移除时，尚未开始且未打印的任务退回待安排；已经开始、已经打印或出纸待核对的任务保留原负责人并标记需要管理员交接。

## 数据安全与并发

- 任务以稳定业务键和轮次去重，跨天和重复同步不复制未完成事项。
- 每次处理、转交、急单调整和任务刷新使用幂等键和任务版本。
- 任务投影版本落后于查询数据时，App 显示提示并禁止任务动作、整单领取和包装确认。
- 准备标签和领取标签都在写事务中重新核对任务负责人、在岗岗位、生命周期和当前数据版本。
- 两台手机不能同时领取同一整单；每台安装继续使用稳定设备 ID。
- 订单数量、摘要或标签内容变化时，已经开始或已包装的任务转为待核对，不覆盖原历史。
- 离线处理保留同一幂等键。网络、超时、429 和服务端错误可以重试；确定性的 4xx 冲突转入本机“待人工核对”，不会堵塞后续队列，也不会自动伪装成功。

员工账号只能查询业务数据、处理本人任务和执行其被分配的包装。完整订单同步、ERP 物流差异写入、未知物流结果确认、人员配置、在岗安排、转交和派工开关均由服务端校验管理员权限。报损报溢成功后的指定商品库存只读刷新仍允许普通员工发起。

## 管理员首次配置

1. 覆盖安装 0.4.0 APK，以原管理员方式登录。
2. 打开“任务”，确认页面显示当前数据时间、任务数据版本和“自动派工未开启”。
3. 在人员管理中为每人建立唯一用户名和初始密码，配置岗位及包装上限。
4. 检查当天在岗状态；兼岗员工可同时选择多个岗位。
5. 在“四岗位总览”核对未分配数量、采购商品聚合、可包装整单、历史已打印待核实及数据待核对事项。
6. 如需固定负责人，添加“客户 → 销售”或“商品编号 → 采购”规则。
7. 确认后开启自动派工。开启动作会立即给当前安全事项分配负责人；旧数据不会给包装人员追加任务。
8. 先让少量员工试用处理、等待、包装、打印和转交，再扩大到全部人员。

员工停用或改岗前，先查看其“包装中、已打印、出纸待核对”事项，并由管理员填写原因后转交。

- `GET/PUT /api/v2/daily-work/settings`
- `GET/PUT/DELETE /api/v2/daily-work/assignment-rules`
- `POST /api/v2/print/jobs/{id}/cancel`：仅取消未领取、明确未发送的准备任务。
- `POST /api/v2/print/jobs/{id}/recover`：领取响应丢失时，使用原领取操作标识将整单转为待核对。

数据库迁移将全局 `user_version` 升到 6：版本 5 增加人员、岗位、会话、任务、处理事件、负责人规则、在岗安排和任务设置；版本 6 增加打印准备的独立幂等标识。所有已有数据库均在结构变更前制作并校验本地一致性副本；完整 SQLite 继续纳入 NAS 加密备份。

## 日常使用

- 订单业务仍由管理员手动点“更新订单”，没有新增定时 ERP 读取或自动业务写入。
- 新一天首次同步前可以查看昨日结转事项，但旧数据不会自动派发新的包装单。
- 销售或采购完成一次沟通后，记录结果和下一次日期；不要为了清空今日列表把未解决事项标记完成。
- 包装人员从“任务”进入整单，按货位、图纸和摘要操作；打印后仍需点“已包装待发货”。
- 主管从总览查看无人负责、逾期、待交接、历史已打印待核实和跨岗位阻塞。
