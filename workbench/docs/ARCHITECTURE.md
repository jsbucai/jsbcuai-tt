# UL 随行：可持续修改的原生 App

## 产品边界

安卓手机使用 Kotlin + Jetpack Compose 原生界面。电脑继续使用 5088。首版交付订单、库存、设备三个可用入口，优先验收连续扫码、数量、范围、拆箱和蓝牙打印；任务看板、进货联查等在此基础上逐项迁移，避免一次替换整套生产系统。

## 清晰的修改位置

| 需要修改 | 主要位置 | 约束 |
| --- | --- | --- |
| 红白黑颜色、文字、圆角、动效 | `app/src/main/java/com/ul/workbench/ui/theme`、`ui/components` | 界面不连接网络或打印机 |
| 订单/库存/设备排版 | `ui/screens`、`ui/WorkbenchApp.kt` | 接收不可变 State，发出 Actions |
| 查询、选择、打印流程 | `WorkbenchViewModel.kt` | 使用同一状态源，忽略过时查询结果 |
| HTTP 与字段转换 | `data/WorkbenchRepository.kt` | 数据缺失保持空值，服务地址可配置 |
| 扫码枪输入 | `MainActivity.kt`、`device/HardwareScanner.kt` | Activity 接收硬件按键，手动编辑时让出事件 |
| A300E 连接与分包 | `device/BlePrinter.kt`、`PrinterTransfer.kt` | 串行、超时、部分发送未知、不自动重试 |
| ERP 文件导入、查询和标签 | `service` | 只读原始文件，独立数据快照与数据库 |

首版使用一个 Gradle app 模块和明确的包边界，减少初期配置成本。设备层与数据接口已独立，可以在后续功能增加时提取独立 Gradle 模块，不需要重写页面。业务状态由 ViewModel 保存以跨越旋转，服务器地址与打印尝试持久化以跨越进程重启。

0.1.1 将订单、库存的查询状态分别保存在 ViewModel 的 `QueryWorkspace` 中，只保存查询条件、结果、选择、分页与数据版本；打印忙碌、未知出纸、服务器和设备连接仍由全局状态统一管理。Compose 用每页的 SaveableStateProvider 保存滚动位置，新查询由 queryRevision 显式触发置顶。切页取消未完成查询，返回时重新完成该页请求，旧响应不能覆盖新页面；同一服务器的连接检查不清除结果，换服务器则清除两页缓存。此缓存不承诺在 Android 杀进程后恢复，避免持久化陈旧业务数据。

库存条件为独立的 InventoryFilters，名称、规格、等级 / 型号、材质按 AND 传到已有 SQL 查询，不拼接成一个 q。扫描新商品会清掉上一组手动条件；分页与全部打印带上相同条件。等级 / 型号对应来源的 model 混合文本，现有语义为包含匹配，不是严格等级枚举。订单导入补齐原表型号；展示先取订单 model，缺失再取关联库存 model，不用备注 grade 冒充。

## 数据与打印的一致性

1. 5191 从原 ERP 文件创建自己的快照，单事务切换数据版本，失败保留旧版并继续检查更新。
2. App 查询取得 `data_version`，生成标签提交 `expected_data_version`；数据变更后拒绝沿用过时的记录选择，重新查询再操作。
3. 服务端冻结快文字 CPCL；App 用唯一动作 ID 单次领取，不因网络超时自动再领或再发。
4. 蓝牙用协商后的 MTU 限制分包，上限 180 字节，沿用旧原生助手的 45ms 分包、120ms 页间节奏。优化来自文字指令缩小数据量。
5. `submitted` 表示蓝牙发送完成，不能代表实体出纸。断线/取消时可能已经发送的任务标为未知，要求核对纸面，禁止自动补打。
6. 成功后撤掉发送状态，清空选择，可继续扫下一件，不打开网页打印预览。

## 视觉规范

用户已指定红、白、黑，参考喜利得与伍尔特的简洁配色，不复制商标。纯白主体、中性浅灰分区、近黑文字，品牌红只承担主操作与选中信息；不使用奶白、墨绿、大面积黑底或无意义渐变。动画服务于选择反馈、内容切换与状态变化。数字可快速辨读，交互区最少 48dp。

已安装并应用官方 `android/skills` 的 `system/edge-to-edge`，固定来源提交 `bac232fd02b0855df9275281a2a7a47643768719`。同仓库最新 adaptive skill 包含实验性布局 API；首版按现有稳定 Compose 工具链实现自适应，不引入这组实验 API。现有 taste skill 只用于设计审视，不把网站技术要求带入原生 App。

## 后续升级规则

- 开发包固定 `com.ul.workbench.dev`，保留同一签名；版本号递增，覆盖安装保留设置。
- 工程内版本配置集中维护，生成 APK 同时记录构建版本与 SHA256；当前开发包使用开发签名，正式发布单独配置签名并安全备份。
- 接口保留 `/api/v2`；添加字段向后兼容，删除或改变语义前提升接口版本，App 显示不兼容提示。
- 标签字段/二维码/包装规则更改必须用 5088 样例对照；常用标签不得静默回退为大位图。
- 每次修改运行对应回归测试；发包前统一执行 assembleDebug、testDebugUnitTest、lintDebug，保留截图与变更说明。
- 不将 APK 升级与原 ERP 写操作绑定；所有业务写入另设明确接口和验收。

## 首版限制与下一阶段

首版依赖同一局域网中的电脑服务。5191 采用私有局域网信任边界，没有设备账号/鉴权，不公开映射到互联网。以后外网访问需要 HTTPS、设备配对与权限、审计日志；离线查询需要有时间提示的本地缓存，离线打印不能直接重放未知任务。

先用真实手机和 A300E 验证纸张内容、扫码枪事件、实际出纸速度与断线恢复；自动化仅模拟传输，不触发实体打印。首版支持硬件扫码枪和手动查询，相机扫码可作为独立输入来源加入同一业务入口。
