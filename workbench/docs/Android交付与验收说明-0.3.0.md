# UL 随行 Android 0.3.0-dev 交付与验收说明

## 1. 交付状态

本说明对应 Android 开发版 `0.3.0-dev`。安装包用于配合已经完成相同版本接口和数据库迁移的 N150 后端进行真机验收。

建议 Android 交付包至少包含：

- `UL-Workbench-0.3.0-dev.apk`
- `current.json`
- `SHA256SUMS.txt`
- 本说明 `Android交付与验收说明-0.3.0.md`

签名文件、ERP 密钥、登录凭据、会话数据和服务器数据库不得放入交付包。

## 3. 覆盖安装说明

### 3.1 推荐方式

1. 确认现有 App 的未上传报损报溢草稿已经记录清楚，不要先卸载 App。
2. 确认 N150 后端、数据库迁移和 Android `0.3.0-dev` 所需接口已经部署。
3. 直接打开 APK 并选择更新现有应用；也可以使用：

   ```sh
   adb install -r UL-Workbench-0.3.0-dev.apk
   ```

4. 安装完成后打开 App，确认登录状态、本机稳定设备 ID、报损报溢草稿和筛选状态没有异常。
5. 按本说明第 6 节完成真机验收后再让两台包装手机同时投入使用。

覆盖安装成立需要同时满足：

- 已安装应用的应用 ID 为 `com.ul.workbench.dev`；
- 已安装应用使用相同签名证书；
- 已安装版本号低于 `9`。

应用 ID 或签名不一致时，Android 会拒绝覆盖安装。此时不要直接卸载旧版，应先导出或处理手机中的未上传草稿。

### 3.2 Android 8 和 Android 9

Android 8、9 在下载原图或保存编辑副本时会申请存储权限。首次使用相关功能时应允许该权限，再检查图片是否出现在系统相册或下载目录。Android 10 及以上使用系统 MediaStore 保存，不需要旧版外部存储权限。

蓝牙打印仍需按系统版本授予蓝牙扫描、连接及必要的定位权限。

## 4. 本版功能范围

### 4.1 订单查询和整单打印

- 订单搜索中的“备注”已统一显示为“摘要”，并兼容旧查询参数。
- 支持全部、未打印、已打印筛选。
- 支持订货日期和交期的起止日期筛选。
- 支持按货位、订货日期或交期排序；空货位排在末尾。
- 全部打印会携带当前完整筛选条件，打印范围应与当前查询结果一致。
- 打印任务按完整订单领取，防止两台手机同时包装同一订单。
- 打印状态包括未打印、打印中、已打印和待核对。
- 已打印或待核对订单可以手动恢复为未打印，并保留服务器端记录。
- 每次安装生成并持久保存稳定设备 ID；准备、领取和提交打印结果使用同一设备 ID。
- 保留原有扫码、拆箱、标签生成和 A300E 蓝牙打印流程。

### 4.2 商品详情、库存台账和产品图

- 库存列表中的商品可以进入商品详情。
- 详情显示商品编号、名称、规格、型号、材质、货位、单位、实物库存和可销售库存。
- 库存历史在打开详情后按需加载，不随库存列表批量下载。
- 台账显示日期、往来单位或单据类型、增减数量、单据号及后续实物库存；余额是否显示以服务器核对状态为准。
- 当前版本最多显示一张 ERP 商品主图，DQ0517 用作主图和历史验收商品。
- 主图支持全屏查看、双击放大、双指缩放、拖动和复位。
- 支持下载原图，并可在手机本地裁剪、旋转、画笔标记、马赛克、撤销、重置和另存副本。
- 编辑副本只保存在手机，不修改或上传 ERP 原图。
- 大图预览和编辑会按最大边约 4096 像素采样，原图下载仍保存原始文件。

### 4.3 报损报溢

- 公网订单、库存、历史和图片继续使用 N150 服务。
- 报损报溢继续使用原电脑的局域网上传服务；离开局域网时仍可在手机保存草稿。
- 草稿按账套和 08390 仓库保存，不再跟随公网服务器地址变化。
- 旧草稿会迁移到稳定账套桶，并按批次 UUID 去重。
- 仅在局域网上传服务健康时允许上传。
- 上传成功表示 ERP 草稿已经建立、尚未过账，不直接修改 N150 的实物库存。
- 上传成功后会请求 N150 小范围刷新受影响商品的当前库存；失败时由后续完整更新补齐。
- 未上传、上传中或待核对的本地调整会在商品详情中显示为“影响可售、未计入实物台账”。

### 4.4 已确定边界

- 业务库存只使用 08390 仓库。
- 客户下拉暂不显示，等待订单数据具备可靠客户关联键。
- 每个商品本版最多显示一张 ERP 主图。
- 图片编辑只生成手机本地副本。
- 报损报溢仍依赖原电脑局域网服务。
- 本包为开发版应用，应用 ID 和签名均属于开发交付配置。

## 5. 上线前置条件

- N150 已部署与本版匹配的 `/api/v2` 接口及数据库迁移。
- N150 已有可查询的 08390 仓库发布数据，并保留最后成功数据版本。
- 商品历史和图片代理接口可用；DQ0517 已在 ERP 中配置主图或图纸。
- 原电脑的报损报溢上传服务在局域网内可达。
- A300E 已与验收手机完成系统蓝牙配对。
- 两台包装手机分别覆盖安装本版，且各自生成不同、重启后不变的设备 ID。
- 正式使用 App 管理打印状态后，不再由其他程序并行修改同一打印业务状态。

## 7. 回退限制与处理方法

Android 通常不允许直接用较低 `versionCode` 覆盖较高版本。因此，安装版本号 `9` 后，旧 APK 不能通过普通点击安装直接覆盖回退。

推荐回退方式：

1. 保留本版 APK、`current.json` 和校验值，先判断问题来自 Android、N150 后端还是 ERP 数据。
2. 若只需回退服务器，先确认旧后端能够读取当前数据库迁移，并且不会破坏新打印状态和库存台账。
3. 若必须回退 Android，应使用与当前应用 ID、签名证书相同且 `versionCode` 大于 `9` 的回退构建，再覆盖安装。
4. 只有在本地草稿、待核对打印和设备状态已经妥善处理后，才考虑卸载再装旧版。

卸载 App 会清除手机本地数据，包括登录会话、稳定设备 ID、未上传报损报溢草稿及部分本地状态。N150 已保存的业务数据不会因此删除，但卸载前必须先处理手机本地草稿和待核对事项。

不要向其他设备复制签名文件。后续 Android 构建必须由受控构建环境使用同一签名，才能继续覆盖安装。

## 8. 验收记录建议

每台手机分别记录以下信息，便于定位问题：

- 手机型号与 Android 版本；
- 覆盖安装前后的 App 版本；
- 公网查询、局域网上传和蓝牙打印的验收结果；
- 测试订单号、测试商品编号和操作时间；
- 打印状态冲突、待核对或上传超时的截图；
- 最终验收人和验收日期。

验收记录不得包含管理员密码、ERP 密钥、Token 或完整登录会话内容。
