# 微信录单与 App 共用草稿

## 使用方式

仅绑定的个人微信可用，映射现有管理员身份；经手人仍由客户已确认的固定销售决定。采购未接入。

1. 发 `录单 客户全名`。模糊名称会列出候选，回复 `选择客户 1`；不猜客户。
2. 连续发送订单文字、图片或 Excel（XLS/XLSX，单份最多 10 MiB）。先发资料后指定客户也可以。
3. N150 的现有 Codex 执行端按 NAS 规则分析资料，结合当前 API 商品目录、客户料号及已核实历史匹配。原表同编码多行分别保留。
4. 微信返回完整核对稿。补充说明直接发送文字，也可在 App 编辑同一份草稿。
5. 确认无误，回复草稿末尾的 `确认上传 XXXXXXXX`。采用本稿、校验原 XLS 各单元格、进入原网页队列。单号唯一、未审核、不自动审核。
6. 微信回传队列和网页结果。网页未明确确认完整导入时进入待核对，不自动重传；本轮不增加销售 ERP 回查。

常用指令：`录单帮助`、`草稿`、`录单状态`、`我的录单`、`打开 会话编号`、`结束录单`。

## 摘要及新建编码

与 App 共用 `SalesAssistant` 和 `sales_web_import`，不复制一套摘要逻辑。

摘要为 `客户订单号#项目号#订单行#客户料号#原品名#原标准规格#原等级#原表面#原数量#ERP编码#交期=YYYY-MM-DD`；G 列摘要与 Y 列明细备注一致。缺交期或字段无法无损表达时提示补充，不猜测。

新商品先显示建议。回复 `准备新品 建议编号` 生成查重及编码方案，必要时附参考商品编码；方案返回后再回复独立的 `确认新建 XXXXXXXX`。创建并核实后重新匹配订单；创建编码不等于确认上传订单。

## 持久化与冲突保护

- App 数据库保存客户、原文、附件、草稿、业务动作及网页执行结果；微信临时日志只存输入去重、待发回复、确认凭据和跨进程恢复信息。
- 仅来自绑定微信、正确机器人、单聊、完整消息的输入进入日志。先落盘再确认接收游标。微信正文及附件不能指定执行账号或绕过业务权限。
- 确认码绑定账套、会话、草稿版本、商品数据版本、固定销售、匹配结果或新品方案。修改草稿后旧码失效。
- 完整核对稿逐段发送成功后才发确认码，不能只收到末尾就确认未展示的明细。发送结果不确定时保留记录，用户可重新请求草稿。
- 每项业务调用先保存原请求和幂等键；重启后使用相同请求恢复，不构造新的上传操作。
- 用户连续补充资料后短暂合并分析，重任务沿用原共享执行通道；草稿版本未变化时只读轻量状态，不重建完整商品匹配。
- 临时原文成功接入 App 一天后清除副本；已发送回复七天后清理正文；完成输入三十天后清理。过期待确认稿清除副本。未指定客户的资料保留七天。执行中事实不按过期自动删除。

## 部署

新增独立 `ul-weixin-sales.service`，320 MiB 内存上限、25% CPU；微信连接仅负责接收和回复，业务进程没有微信登录凭据。沿用 App 的管理员权限核验及销售/Codex/新建商品/网页队列，不改变 APK。

配置 `/etc/ul-weixin-sales/config.json` 仅 root 可读；临时日志 `/var/lib/ul-weixin-sales/bridge.sqlite3` 仅 root 可读。正式历史使用原固定 SHA256 的 NAS 迁移索引。微信销售服务独立持续运行，巡检通知仍按原观察期限结束。

回退时停止销售接入服务并将销售配置 disabled；保留 App 草稿、附件、已确认操作和微信日志，不覆盖业务数据库。已进入原业务队列的上传需核对其原记录，不能通过回退重新发起。

## 验收范围

自动测试覆盖文本/图片/Excel 共用 App 数据、重复消息与断点恢复、草稿和商品版本冲突、新品独立确认、同编码多行、摘要末尾交期、媒体解密与大小限制、非绑定发送者拒绝、完整草稿发送依赖、通知与业务限流隔离。

实际微信三种输入、Codex 真实分析、用户确认及真实网页上传分别记录现场结果；不能以单元测试或服务启动替代真实订单验收。
