# 销售网页导入确认与恢复

本次按用户最新要求调整验收：确认稿和 XLS 校验通过，网页明确报告全部明细导入完成，即记为“网页已确认导入”。上传后不查询 ERP，不进入单据编辑器，不审核订单。2026-10-07 已发布 App `0.4.10-dev`、后端 `0.5.15-file-only` 并启用网页销售执行器；没有上传额外样单，首次真实自动销售导入仍待观察。

## 执行链

1. App 确认稿冻结客户、商品身份、每行单位来源、税价、摘要、附加说明和交期；队列锁定唯一单号及确认版本。
2. N150 首次执行检查当前网页账套、职员与精确客户绑定，生成并逐单元格校验 XLS。不同明细交期按 XLS 各行保存，不再因不能逐行回查而拒绝。
3. 在唯一上传操作前先持久化 `attempt.json`。同一账套、账号和单号只能由原意图占用，重复请求不得成为第二次上传。
4. 成功依据是网站完整导入日志：开始、格式检查、本次 N 行写入及编号完成项；N 与校验文件行数一致，并且没有失败、部分、跳过等提示。按钮点击或笼统“完成”不算成功。
5. 将绑定单号、文件 SHA256、行数及网站日志的确认写入 `completed.json`，再原子更新录单会话与网页队列。

成功结果保留 `status=imported`、`code=web_import_confirmed`、`completion_basis=web_import_confirmation`、`erp_readback_performed=false`、`table_verified=true`、文件校验值和导入行数。队列状态为 `succeeded`，会话为 `submitted`；`unit_verified=false`，不能把表格单位来源写成 ERP 回查证据。

## 中断与未知结果

兼容命令 `--readback-only` 和 `reconcile-sales` 现在仅恢复本地确认记录：不读取登录凭据、不初始化浏览器、不查询客户或订单、不进入编辑器、不再次上传。没有原上传标记，或有标记而无有效确认记录，保持“导入待核对”，交由人工核对；没有安全人工结案入口时不自动结案。

旧 `verified.json` 或单独 `progress.json` 不替代本次确认。响应丢失、浏览器异常、确认记录未落盘、字段缺失或校验不符均保持未知，禁止以恢复为由重新上传。原销售意图和单号保持冻结；其浏览器进程关闭、执行槽锁释放后，其他独立订单及采购下载可以继续，避免一张无回执销售单永久阻塞公司队列。仍运行、等待人工验证和结果不明的采购操作继续占用执行槽。

恢复过程中沿用原进度上限，不能把已到第二步的中断任务强制退回第一步而导致恢复失败。

## 发布时需要对齐的配置

共享 worker 默认固定配置路径为 `/etc/ul-sales-web-worker/config.json`，字段 `enabled` 与 `acceptance_complete` 仍保留；其验收依据应为模板、冻结稿、单位来源及网页完整导入确认，不再要求 ERP 回查或 `readback_unit_basis`。配置继续要求受限权限、账套、职员、允许经手人、仓库及模板 SHA256；不将凭据复制到 App 或普通交付文件。

客户完整名称与 ERP ID 的固定绑定不会在 24 小时后失效；绑定仍需有明确时区的合法时间，超过 5 分钟的未来异常时间不可用。首次上传之前始终重新抓取完整 ERP 单位字典，精确比较名称、ID、账号、账套、唯一性及有效状态；改名、换 ID、重名、停用或查询不完整仍阻止上传。该即时核验不能被旧绑定代替，也不属于上传后的 ERP 回查。

`build_customer_bindings()` 可在一次完整只读字典请求中生成所有唯一名称的有效绑定，返回绑定表、目录行数及排除行数/原因。同名记录全部进入待核对，即使其中一条停用也不能自动择一；每个绑定的校验摘要与单客户构造流程一致。此函数只产生候选数据，不改生效配置或业务库。

只读 `sales_web_host_preflight.py` 仍核查新鲜网页身份、客户、职员及仓库字典，但不再要求 `exact_number_query_complete`。它生成的候选配置默认关闭写入；本次主流程已按用户授权在 NAS 备份后安装受限配置并启用正式模式，主机与后台开关、账号及账套核验一致。配置、凭据与私有核验资料未写入普通交付文件。

## 本轮离线验证

`service/tests/test_sales_web_operation_worker.py` 覆盖：相同 SKU 分行、不同明细交期、单位来源、完整网站确认、响应丢失、禁重传、无登录或 API 的本地恢复、缺标记、账套及职员身份、旧 verified 结果拒绝、新确认字段及行数严格校验、已推进任务的重启恢复。共享队列测试继续验证幂等、唯一目标、权限与采购下载回归。
