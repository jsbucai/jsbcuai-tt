# UL 随行公网入口与 0.2.2 交付

更新：2026-09-26。**公网连接和登录已部署；完整 ERP 业务数据接入仍在开发，不替代原版生产使用。**

## 使用方式

- NAS 项目根目录安装 `UL随行-0.2.2-dev.apk`，原签名覆盖升级即可。
- 服务地址：`https://ul.yingyinghome.com:8443`。
- 登录密码沿用用户此前提供的密码；服务器只保存密码哈希，本文件不记录密码。
- 新安装默认使用 8443。此前保存的 UL 无端口地址或显式 443 地址自动迁移；其他自定义服务器地址保留。
- 尚未发布首份业务快照时，App 明确显示“尚未完成首次数据同步”。能登录不等于订单、采购、报损报溢已全部接入。
- 用户已通过手机实际输入管理员密码并确认登录成功。

## 实际部署

| 项目 | 当前配置 |
|---|---|
| 业务虚拟机 | Proxmox VM 103，Debian 12，2 vCPU、2 GB RAM，192.168.100.31 |
| 磁盘 | 宿主 local 目录上的 16 GiB raw 磁盘，已实际预留，不占用原 local-lvm 精简池；宿主预留后约剩 12 GB |
| 服务 | `/opt/ul-workbench`，Docker Compose，镜像 `ul-workbench:0.2.2`，非 root 容器 |
| 数据 | 虚拟机本地 `/opt/ul-workbench/service/runtime/data`，SQLite 不在 SMB 上运行 |
| 内网接口 | `.31:5191`，DOCKER-USER 限制仅 Caddy `.30` 入站访问；公网没有 5191 转发 |
| 公网入口 | 现有 CT 102 Caddy 新增 UL 的 8443 虚拟主机，家庭站点保留 |
| DNS | `ul` CNAME 指向已有 `vpn.yingyinghome.com`，跟随原家庭 DDNS |
| TLS | 独立 Let's Encrypt 证书，阿里云 DNS 验证，覆盖 `ul.yingyinghome.com` |
| 自动续期 | 复用路由器 ACME 每日 04:17 任务；CT 102 的 `ul-cert-sync.timer` 每日 05:15 左右验证、同步并热加载证书 |
| 业务任务 | 仍只手动触发，没有新增定时业务同步或 ERP 写入 |
| 备份 | 每日 03:15 左右在线一致性备份，加密后写 NAS `开发项目/UL随行/N150备份` |

为解决证书服务与官方容器仓库出站 TLS 失败，仅新增 `letsencrypt.org`、`docker.io`、`docker.com` 的代理规则，使用现有自动选择组；未切换默认出口。规则写入现有 OpenClash 自定义规则和当前配置，原配置已备份。证书续期命令显式使用已验证代理，阿里云 API 直连。

Debian 镜像从中科大镜像站取得并核对 SHA-512；Docker 软件包签名指纹已核对。容器构建支持可选 APT/Python 镜像参数，本机部署采用中科大 APT 与清华 PyPI，均保持 TLS 校验。
