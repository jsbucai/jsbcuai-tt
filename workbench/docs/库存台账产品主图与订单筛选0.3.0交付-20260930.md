## 已交付功能

### N150 后端

- 继续使用一个 Flask 服务和一个本地 SQLite 数据库，没有增加 Redis、数据库服务器或消息队列。
- 所有库存、订单关联、库存流水和局部库存刷新只处理内部仓库 ID `29871293290508390`，即 08390 仓库。
- SQLite 升级到 `user_version=4`，新增库存流水、库存锚点、同步水位、商品图片元数据、整单打印状态和审计数据。
- 日常库存台账按上次水位前 72 小时重叠读取；每满 7 天，在下一次手动业务更新中自动执行完整核对。没有独立的业务自动更新任务。
- 台账覆盖进货、销售、报损报溢和生产组装等单据。没有真实样本或方向尚未验证的类型会保留原始记录并把余额标为待核对，不生成伪造余额。
- 商品主图只允许固定 ERP 图片域名，经 N150 按需代理和缓存；SQLite 只保存元数据和内容哈希。
- 订单查询支持摘要、打印状态、订货日期、交期、物流分类与货位／日期排序；空关键词也可以使用结构化筛选。
- 打印协调按整张订单加锁并记录设备 ID、标签指纹、打印中、已打印和待核对状态；内容变化会使旧指纹失效。
- 报损报溢上传成功后可按商品 ID 执行 `inventory_subset`，只重读相关商品的 `qty/saleqty`，不会写 ERP 或直接加减实物库存。

### Android

- 公网查询固定使用 N150；报损报溢固定使用原电脑局域网地址，草稿不再跟随公网服务器地址变化。
- 新增商品详情、按需库存历史、产品主图全屏查看、缩放、下载、旋转、裁剪、画笔、马赛克、撤销、重置和保存副本。
- 图片编辑结果只保存在手机，不修改或上传 ERP 原图。
- 新增全部／未打印／已打印、订货日期、交期、货位与日期排序；“备注”已改为“摘要”。
- 打印由选中明细扩展为整张订单，同一订单只能由一台设备领取；未知出纸进入待核对，不回到未打印列表。
- 保留扫码、拆箱、A300E 蓝牙打印和原有红、白、黑界面。
- 客户下拉继续隐藏，因为当前订单数据没有稳定的非零客户关联键。

## 尚需真机／业务验收

以下项目需要设备或业务操作，不能由本次服务器只读验收代替：

1. 先在一台手机覆盖安装，确认登录、稳定设备 ID 和旧报损报溢草稿保留，再安装第二台。
2. DQ0517 在手机上完成缩放、下载、裁剪、旋转、画笔、马赛克和保存副本；Android 8／9 另验旧存储权限。
3. 两台包装手机同时领取同一整单，验证只有一台成功；再验证 A300E 实际出纸、未知出纸和手动恢复未打印。
4. 在原电脑局域网服务可用时上传一笔报损或报溢，确认只建立 ERP 草稿，并触发受影响商品的 N150 局部库存刷新。
5. 为订单摘要补齐末尾 `#交期=YYYY-MM-DD` 后重新手动更新，核对分类结果。物流写回仍需单笔和小批量业务验收后单独开启。
