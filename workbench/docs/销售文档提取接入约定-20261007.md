# 销售图片和 PDF 提取接入约定

本模块只读取已保存的录单附件。不会浏览 ERP、调用 Codex、下单、付款、确认或自动更新销售草稿。生产服务尚未安装 PDF/OCR 依赖；提取成功不等于商品匹配成功。

## 事务与运行边界

`SalesDocumentPipeline(store)` 初始化新增表；已有销售会话和附件表须先创建。上传在同一 SQLite 事务中保存附件行，再调用 `enqueue_document(db, attachment_id)`。重复调用返回同一任务；附件的 hash、会话、文件名身份被改动则拒绝。上传请求不运行提取器。

独立 worker 调用 `run_one(worker_token, tesseract=None)`。每个数据库同时只允许一个重任务，提取期间不持有 SQLite 写锁。子进程有 30 秒墙钟限制，Linux 有 512 MiB 地址空间和 20 秒 CPU 限制；超时杀停整个进程组。原件最多 10 MiB、50 页、总文字 200,000 字符。完整草稿候选上限 500 行，超限保持阻断，不发布前 500 行作为完整结果。可选命令：

```sh
PYTHONPATH=service python service/tools/sales_document_worker.py --runtime service/runtime/独立测试目录
```

此工具每次只提取一个任务，未配置 Tesseract 时图片返回明确缺少依赖。启用 OCR 还需要绝对可执行路径和包含中文的实际语言模型，例如 `--tesseract-command /usr/bin/tesseract --languages chi_sim,eng`。不会下载依赖或模型，不会临时安装到生产 N150。

## 读取与显式采用

调用方必须先通过现有销售权限和固定客户归属检查，再读取 `status(db, session_id, attachment_id=None)` 或 `result(db, session_id, attachment_id)`。

状态查询只选轻量列，不读取大结果 JSON。返回 `queued/running/ready/failed/adopted`，以及 `message/error_code/page_count/line_count/candidate_count/source_row_count/unready_pages/result_hash/adopted_version`。`ready` 只表示所有页面得到了候选文字；`failed` 仍可能含部分页面的提取结果，原件及已提取文字不会丢失。`adopted` 表示第一次采用的草稿版本已留档，不能代表完整识别或订单确认。

`result()` 另返回 `extraction` 和 `projection`。投影含 `lines` 与 `source_rows`。每一实际文本行保留附件 ID、全文件 SHA256、页码、行号、方法及完整原文，ID 固定为 `document:附件ID:hash前16位:页码:行号`。同 SKU 出现两行不会合并。

目前仅完整的“商品编码,数量,单价”或两/三列空白分隔行产生明确编码候选。其余原文生成未匹配候选，需要人工选编码或明确排除。不会把表格之外正文自动丢掉，不会把 PDF 自动文本提取称为完整的自然语言订单识别。

显式采用端点先执行权限、请求幂等和草稿版本检查；比对服务端结果 hash；若 `adopted_version` 已有值，则返回原采用结果，不能再次追加。未采用时在同一事务把候选和来源表加入草稿，再调用 `mark_adopted(db, session_id, attachment_id, result_hash, 新草稿版本)`。上传时的待采用来源 blocker 只能在此事务替换成真实来源结果。采用不是确认，后续仍要逐行核对、冻结版本和最终 ERP 回查。

## 覆盖与人工排除

`kind=document, scope=extracted_line, exclude_allowed=true` 表示已提取的实际正文行，可由现有人工排除动作提供原因并保留记录。`scope=page_coverage, row=line=0, exclude_allowed=false` 表示页面/全文没有可靠可核对文字，不能通过删除来源行或填写排除原因解除。

扫描 PDF 无文本页、加密文件、缺少依赖、文件损坏、资源超限和完整性失败都保留覆盖 blocker。后续可另行设计“补充文字或 Excel → 明确替换原件覆盖 → 人工确认”的核对动作；本轮未实现，不得静默解除。

## 当前验证

独立测试覆盖实际两页 PDF、空白末页、原始文本与页面身份、重复 SKU、上传/排队回滚、工作租约恢复、旧 worker 拒绝、状态查询不读正文、提取时其他写事务可立即执行、结果 hash 与原子采用、文件完整性异常和进程超时。

初始模块测试时尚未完成真实 N150 OCR 模型验收与扫描 PDF 转图识别；下方记录随后进行的隔离验收，生产启用仍需单独通过发布门槛。

## 当日补充：N150 隔离 OCR 验收

后续在 `/opt/ul-sales-runner/deps/ocr-20261007` 单独下载并提取 Debian 官方包，实际运行 Tesseract 5.3.0、Leptonica 1.82.0、chi_sim/eng 模型；独立新 venv 安装 pypdf 6.19.0。未执行系统级安装，未更改活跃采集 venv，未启用文档 worker 或重启服务。系统 dpkg 的这五类 OCR 包仍未安装。

仅使用合成 PNG 和两页文本 PDF。实际 OCR 完整提取两行 `LS1000,1,1.13`、`LS1000,2,1.13`，中文标题和测试客户名称匹配，耗时 0.452 秒。空白图、缺中文模型和错误文件签名都返回准确失败状态。Linux 有界子进程读取两页 PDF，未丢最后一页。

版本、八个 deb 包、执行文件、模型及输入图片的 SHA256 保存于 `outputs/evidence/n150-ocr-20261007/environment.json`，真实结果保存于同目录 `real-ocr-validation.json`。这证明隔离运行和干净合成图可行；真实手机照片、倾斜、手写、复杂表格和扫描 PDF 转图准确性仍需另行验收，不应被称为全部录单识别已通过。
