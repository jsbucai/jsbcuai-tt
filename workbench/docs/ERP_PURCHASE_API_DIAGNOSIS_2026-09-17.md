# 采购接口空结果：进一步只读排查

核查时间：2026-09-17，最新实测约 12:56（北京时间）。

## 当前结论

目前尚未取得未完成采购订单数据，不能断言接口不支持采购订单，也没有证据确定根因为某个 ERP 设置。

更值得核查的是 **ERP 普通进货单与云仓/PDA 入库管理记录之间的数据范围或关联**。依据是：同一授权账号能从单据中心读取实际进货入库单，但使用这些单据的真实编号、来源主键查询云仓入库接口仍为空。此结论为排查方向，不是已经确认的根因。

用户确认平时在电脑 ERP 直接做进货入库单。本轮用户自行关闭了“入库单只能调用进货订单”的设置；以下关闭后的查询仍为空。该设置的实际保存状态、适用模块及历史记录是否受影响，未通过 ERP 页面验证。

## 已确认的参数规则

- [512 范围查询](http://d7safe.mygjp.com.cn:8020/web/#/erpapi/512)：`erp.ewms.stockinbill.list`；`timetype=0` 为入库单创建时间，`1` 为交货时间。可选 `number`、`processstatus`、`ownerid`。
- [509 出库范围查询](http://d7safe.mygjp.com.cn:8020/web/#/erpapi/509) 的 `timetype=1` 是修改时间，不能将它套到入库接口。
- [673 精确查询](http://d7safe.mygjp.com.cn:8020/web/#/erpapi/673)：`erp.ewms.stockinbill.query`，无需时间参数，单号、来源 ID、入库单 ID 三类条件至少一类，每类最多 200 个。
- 673 字段表使用 `Numbers`、`SourceIds` 等写法，但 [299 公共参数](http://d7safe.mygjp.com.cn:8020/web/#/erpapi/299) 明确“所有参数默认使用小写”。顶层业务参数本轮使用 `numbers`、`sourceids`、`processstatus`。不能将 JSON 参数值整体转小写。
- 收货状态按 673 定义显式覆盖 `[0,1,2,3,4]`：待收货、部分待收货、收货中、完成、挂起。
- `ownerid` 是章鱼侠 WMS 提供的货主 ID；没有取得可信的实际货主 ID，因此未猜填账套 ID。

### 实际发现的签名问题

按字段表直接发送大写 `Numbers` 时，现有签名实现收到 `errorcode=10`、`签名错误 sign`；仅改为不区分大小写排序仍错误。

按公共规范改为小写 `numbers` 后，同一方法通过校验，`iserror=false`，但 `orders=[]`。因此修正了精确查询的调用问题，**并未解释此前一直使用小写参数的范围查询为什么为空**。未修改生产客户端的签名实现或方法权限列表。

## 为什么要核对数据范围

[513 共享模型](http://d7safe.mygjp.com.cn:8020/web/#/erpapi/513) 列出 `vchtype=7` 进货订单和 `34` 进货入库；同时分别定义入库单主键 `vchcode` 和来源单据主键 `dlyndxvchcode`，示例错误称为“PDA入库管理单”。这表明来源业务单与入库管理记录存在不同的实体标识。

[官方云仓入库任务帮助](https://helpnew.wsgjp.com/98ad/3248/611a/b99a) 描述了提交云仓后进入任务的流程。该帮助属于云仓业务分支，不能直接证明当前账套的自有仓/PDA 行为相同，只能作为核对入口。

此外，`qty` 文档仅定义为数量。即使后续查到数据，仍需与部分到货、终止、补订、单位换算的样本对照，才能作为“采购未完成数量”使用。
