# 草稿占用推算与后端 1.4.5 交付

日期：2026-10-02

## 业务口径

同一账套、08390 仓库、商品、SKU 和基本单位下，先汇总全部活动销售需求及已出库未记账的影子需求，再计算：

`净调整 = 可销售库存 - 实物库存 + 全部销售未完成需求`

- 净调整大于或等于零：作为采购／改制未到数量。
- 净调整小于零：作为 ERP 已计入可销售库存的推算其他占用；采购未到记为零，并以 `实物库存 - 推算其他占用` 作为 FIFO 可用现货。
- 推算其他占用通常来自组装、报损、销售出库等草稿或其他保留量。库存 API 三个总数只能证明存在净占用，不能证明具体单据类型，因此接口和报告不把它冒充为已读取到的草稿明细。
- 缺页、订单与库存身份不完整、数量无效、入库账本冲突等问题继续阻断，不能伪装成草稿占用。

该处理不是把负数简单改成零。其他占用必须先从实物库存扣除，再判断后续订单是否仍需采购。

## 已确认实例

LS2261 的实时数据为实物库存 165、可销售库存 16、销售需求 144。管家婆“可销售库存占用分析”显示组装拆卸单草稿 `ZZ-20260921-002` 占用 5，因此：

`16 = 165 - 144 - 5 + 0`

新规则得到采购未到 0、推算其他占用 5、有效实物库存 160。`26975764#29` 和 `26975764#30` 不再因负采购未到而计算失败；其最终物流分类仍由 FIFO、来货批次及第八天异常规则决定。

## 实现

- 完整同步、完整分类和库存子集刷新使用同一供给拆分函数。
- 库存 JSON 保留非负 `purchase_pending`，新增 `inferred_other_reserved` 和 `effective_physical`；旧 Android 会忽略新增字段，无需更新 APK。
- FIFO 使用有效实物库存；入库账本仍以原始实物库存核对，临时草稿占用不会永久消耗入库流水。
- 规则版本升级为 `5-api-4`。SQLite 结构不变，无需数据库迁移。
