# 给原电脑 Codex：API 字段补充核验

本轮目标是让 N150 直接读取管家婆，App 手动触发更新。已收到 9 月 25 日补充回复及分类基线；以下只补尚未闭环的字段，不需要重复打包 Android 工具链、密钥或整份项目。

**只做读取和对照，不创建单据、不发货、不记账、不修改业务设置。** 若尚无经过实测的读取接口，请直接写“未找到”，不要将字段名相似或接口空结果当成验证通过。查询入口与物流写回可分别验收：缺少分类资料的订单仍可查询，但不能据此写物流。

## 一、优先补齐：订单交期、剩余数量与状态

请给出能与《销售订单统计列表数据.xls》逐行对应的**实际 API 方法、有效请求参数及返回字段路径**，覆盖：

| 需要的事实 | 对照与判定要求 |
|---|---|
| 完整订单和明细身份 | 完整订单号、订单主键、明细主键；说明与 WMS `tradeid/sourceid/goodslist[].sourcedetailid` 的关联，不使用仅有订单号的模糊匹配 |
| 交货日期 | 对应销售统计 L 列“到货日期”；不要使用创建时间、修改时间、当前日期，也不要从现存物流单号反推 |
| 剩余未完成数量 | 对照订货数量、已完成数量、终止数量、未完成数量；说明返回的是原始订货量、待发货量还是剩余量，以及基本单位换算 |
| 结束与终止状态 | 全部完成、部分完成、部分终止、全部终止／关闭各自如何返回；这些订单是否从范围查询消失，如何避免遗漏旧未结束订单 |
| 稳定库存维度 | 账套、仓库 ID、商品 ID、SKU ID、基本单位及换算率；显示名称只能辅助对照 |

请从已有真实单据选 5 类样本：未发货、部分完成、部分终止、全部终止／关闭、多明细订单。可由一张单据覆盖多类；没有某类则注明。每条同时保存 ERP 页面／导出值与脱敏 API 对应值，记录查询时间。另列一份全量未结束订单与 API 结果的数量及差异清单，不能只验证最近新增订单。

同一完整订单号若出现不同交期，请提供现存样例；没有样例就注明“未观察到”。当前实现遇到日期冲突会停止该订单物流写回，不自动选第一条、最早或最晚日期。

**已知限制，不必重复按原参数试一遍：**

- 既往奇门 `qimen.taobao.erp.order.sync` 的 `sell_count` 只验证为销售数量；交期未找到，未完成／终止状态未闭环。
- WMS `erp.ewms.stockoutbill.list/query` 的 `deliverstatus` 只定义未发货／已发货；现有研究没有证明 `goodslist[].qty` 等于销售剩余需求。
- 文档 510 提到 `extendprops`，但没有可用交期字段定义；9 月 26 日近期读取也未取得该字段中的交期。若原电脑存在有效扩展字段或另一接口，请提供真实路径及正例。

## 二、采购与改制：只补催货所需批次

**用户已修正并确认：采购未到总量＝库存数量－可销售库存＝库存查询的订单数量＋改制单数量。** 改制计入采购未到；9 月 25 日以前文档中的“可销售库存－实物库存＋销售需求”旧公式已作废，不再验证或沿用。

总量已经有方案；这里需要的是每笔普通采购及改制／委外的**批次日期、供应商、剩余量**，用于催货：

- API 方法、真实请求条件及返回路径；单据／明细 ID、仓库、商品／SKU、基本单位。
- 订货／改制日期、预计到货日期（若存在）、供应商 ID／名称、未到数量、完成／终止数量和状态。
- 至少对照一笔完全未到、一笔部分到货、一笔终止、一笔改制／委外。说明退货后是重新形成未到需求还是另开单，不能直接推断。
- 同一库存维度下批次剩余量与 `qty - saleqty` 的核对；差额属于哪种业务必须有依据。缺少批次时不虚构日期或供应商。

现有证据中 `erp.ewms.stockinbill.list/query` 对 58 个历史未完成采购样本及已知入库正例均为空；`beefun.gjsstockbilldetail.list` 是已过账入库，不是未到采购。若你找到非空读取路径，请给一笔可复现正例；如需厂商确认模块范围或 `ownerid`，请提供核实结果，勿猜填账套 ID。

## 三、实际入库与旧分配账本

`erp.bill.billcenterlist`、`vchtype=[34]` 已有实际入库样本对照。无需重新证明普通正向入库能读，主要补：

1. 一组原进货单＋退货单、一组原单＋红冲单，返回原单关系字段、符号／`inout`、仓库和单位；明确是否同时保留原单与冲销事件。官方 `redold/redword` 标志本身不足以建立原单关系。
2. 明细唯一键和排序依据：`vchcode + dlyorder`、过账时间 `overtime`、录单日期 `date`。若以其他字段关联请提供原始路径；同一秒多单不能仅靠日期去重。
3. 冻结当前实际使用的 `入库批次` 台账及导出截止时间，提供“旧事件 ID → API 单据／明细 ID、旧仓库＋商品编码 → 五维库存身份”的映射表；核对已分配数量、剩余数量及订单上的分配关系。不得清空旧账本后把同一到货再次分配。
4. 历史读取起点要覆盖仍有余额／仍被未结束订单引用的最早批次，并说明退货与红冲的补读范围；只取最近几天不能算完整初始化。
