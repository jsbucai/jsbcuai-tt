# 销售订单 API 接入待确认

日期：2026-10-07。用途：请管家婆接口支持人员逐项提供正式合同与测试账套验收依据。本清单不含凭据、客户样本或生产单据，不授权执行新增、审核、出库或修改。

UL随行拟在员工确认草稿后创建**未审核销售订单**，随后按唯一标识逐字段回查；结果不确定时只查询，不自动重复提交。目前尚未启用真实写入。

参考：[新增销售订单 `erp.saleorder.add`](http://d7safe.mygjp.com.cn:8020/web/#/erpapi/572)。现有 [WMS 精确查询](http://d7safe.mygjp.com.cn:8020/web/#/erpapi/672)、[销售出库单明细](http://d7safe.mygjp.com.cn:8020/web/#/erpapi/698) 与 [奇门发货单查询](http://d7safe.mygjp.com.cn:8020/web/#/erpapi/1781) 尚不能证明覆盖该方法创建的未审核销售订单。

## 请逐项确认

| 项目 | 需要厂商明确回答 |
|---|---|
| 1. 创建状态和业务类型 | `saleorder.add` 创建的是哪种销售订货单？默认是否未审核，能否显式指定？是否触发审核、转销售出库、记账或其他自动处理？请给状态字段、值域与权限要求；不能用发货状态代替订货单审核状态。 |
| 2. 单号唯一性与幂等 | `number` 的长度、字符及唯一范围是什么（账套、单据类型、历史/已删单）？同号同内容、同号不同内容分别拒绝、覆盖还是新增？有无正式幂等键/外部引用字段，引用能否持久保存并精确查询？返回 `vchcode=0` 是何种结果？ |
| 3. 创建后回查 | 请提供未审核销售订单**表头及明细**的只读 method、完整参数/响应与实际样例：能否按返回 vchcode、指定 number 或外部引用精确查找？多久可见？能否读取消/删除/已审核记录？如何确认分页完整与“未找到”，而非权限不足、延迟或范围遗漏？若使用 WMS/奇门，请证明对应关系及未审核覆盖。 |
| 4. 同 SKU 重复明细 | 新增明细是否支持上传并回读外部行引用？ERP 返回的永久明细 ID 如何与上传行一对一绑定？同 SKU 两行、数量/价格相同或不同，是否自动合并或重排？不能仅凭商品、金额或行顺序猜对应关系。 |
| 5. 税价与舍入 | 现有业务规则为税率 13%；未注明未税的客户报价按含税，除 1.13 后未税单价保留三位，行金额保留两位。请确认 `assdpprice`、`asstpprice` 是否未税、折扣如何计算、`tax` 是否传 13，以及表头 `total` 应传未税还是价税合计。请明确单价/行金额/税额/整单的精度、舍入方式及先后顺序，给带小数数量的可核验例子。 |
| 6. 经手人与制单人 | `etypeid` 是否仅代表业务经手人？制单人是否固定为 Token 的 employee_id？有无独立制单/操作者字段及权限限制，回查返回什么 ID？若由中心授权职员提交、经手人为客户固定销售，ERP 如何记录两者？不能把经手人等同于制单人。 |
| 7. 客户订单号与人工说明 | 客户 PO、外部唯一提交引用、客户原始行号分别应放哪个正式字段？能否原样回读，长度/字符限制是什么？`comment` 自动追加的系统说明是否固定可区分？如何保留人工备注，避免用于绑定的引用或客户 PO 丢失、截断或改写？ |
| 8. 仓库与交期范围 | 当前合同只有表头 `ktypeid`、`todate`。是否支持明细仓库、明细交期？若不支持，是否必须一仓一交期分单？请明确拒绝行为，不能静默采用表头覆盖明细。还需确认录单日期/交期格式、时区及不可填写日期。 |
| 9. 商品、SKU 与单位 | `ptypeid + prop1 + prop2` 如何精确指定已有 SKU，是否另有 skuid 参数？无属性商品 0/0 是否正式支持？基本单位 `unit=1,unitrate=1`、单位名为空时能否稳定录入并回查？本项目基本单位已确认是“支”，不据此推断辅助单位或包装换算；停用/删除或身份不唯一时应怎样拒绝？ |
| 10. 字典与查询一致性 | 请明确客户/职员字典的过滤、分页总数语义及空集合返回规则。`employee.listall` 的主键应使用 id 还是 employeeid？过滤后 totalresults 是否仍可能为全目录总数？如何取得可证明完整且唯一的客户、职员、仓库与商品身份？ |

每项回复请包含：正式文档链接/版本、method、字段名称与值域、权限/限制、脱敏请求和响应、错误码；不支持的能力请明确写“不支持”，并说明官方替代接口。

## 最小测试账套验收顺序

测试仅使用隔离测试账套及测试字典，取得明确测试授权后执行；本文件不包含测试登录信息，也不要求在生产账套试单。

1. **只读预检。** 核对账套、授权制单职员、经手人、有效客户/仓库/商品/SKU/基本单位；验证唯一查询及分页边界。记录合同版本与冻结草稿。
2. **一单一行。** 持久化提交意图和唯一引用，只发送一次。按官方回查接口核对单号/ID、客户、人员、未审核状态、商品/SKU、数量、单位、税前/税后价、税额/总额、交期、客户 PO 与备注。确认未自动出库或记账。
3. **税价和范围。** 使用少量合成数据验证三位单价、两位金额、小数数量及舍入；验证混仓/不同行交期的明确支持或拒绝。不得丢弃字段后视为通过。
4. **重复行与重复号。** 同 SKU 两行分别测试同数量不同价格、不同数量同价格，证明永久行 ID 与外部行引用正确对应；在厂商明确的重复请求合同下受控验证重复号不会覆盖或重复创建。
5. **中断与恢复。** 模拟发送后丢失响应、进程重启和查询延迟。已有持久化意图只回查，不盲重提；未找到、多结果、字段不一致或无法证明完整时保持待核对。回查确认后仍不得再建第二单。
6. **权限及验收留档。** 验证错误账套、无写权限、失效身份、停用商品等明确拒绝；保存脱敏请求、业务响应、唯一表头/明细回执和 ERP 页面对照。全部通过前维持真实提交关闭，不接生产定时任务。

验收通过的含义是唯一订单及每行都能与冻结稿核对，且未审核状态可证明；HTTP 成功、导入完成文字、订单总额相同或查到已有发货单均不能单独作为通过证据。
