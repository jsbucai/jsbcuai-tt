# UL随行 0.4.9-dev／后端 0.5.14：网页操作队列

2026-10-07 在 N150 发布。采购网页下载已由原独立计时器切到单浏览器队列；销售、采购订单导入占用同一队列类型，但没有启用外部提交执行器。手机销售录单与采购助手顶部可查看网页操作的排队、当前步骤、待人工核对及结果，并可手动刷新。旧版客户端不受新只读接口影响。

## 已完成

- SQLite 新增 `web_operations`、冻结参数、事件三类表。一个浏览器执行槽，按入队顺序认领；同一操作者幂等键及同一业务目标不能重复入队。
- 运行中重启：采购下载保留人工核对状态；可能已上传的单据标为结果不明并阻断后续执行。不能自动重发。成功必须带可核对的文件快照或 ERP 单号。
- N150 的 `ul-purchase-trial.timer` 已停用，改用 `ul-web-purchase-enqueue.timer`（北京时间每日 07:40、11:40、16:10，周末照常）及 `ul-web-operations-worker.service`。原采集脚本、账号、隔离浏览器、验证码人工等待和试验快照路径不变；与 07:30、11:30、16:00 的 API 更新错开。
- 14:59 的额外只读试跑入队为 `92f8d0f1e2d84bf8b4ef39113eff67ae`，实际经过运行及文件核对，完成快照 `20261007T070101Z-6561e7e1ac61-abb8b74f`：96 行，网页行数与文件行数一致，工作簿 SHA-256 `6561e7e1ac61c446d39f6bfd20cc6ed92d90c76ce183802cb9254de8be8f8994`。这次不是 16:10 定时触发的验收。
- 试验快照仍标记 `units_verified=false`、`coverage_complete=false`、`formal_business_publish=false`；不会覆盖正式采购未交业务快照。

## 尚未开放的写入

销售网页导入已有一张人工试单的唯一单号回查和离线单次传输实现，但缺少 N150 自动登录、原账号及单位字段的完整闭环验收，手机提交仍关闭。采购订单网页导入还没有经实测的模板、未审核状态及精确回查适配器；采购平台自动下单、付款和 ERP 补录也没有启用。队列只负责顺序、进度和中断保留，不会凭“上传按钮已点击”宣布订单成功。

下一步是把销售确认稿冻结为队列目标，用同一个 worker 完成单次网页导入及原单号回查；再以已付款平台订单为采购录入目标，独立验证 ERP 采购模板、单位、金额和未审核状态。两个执行器均需在各自验收后才能开启手机提交按钮。
