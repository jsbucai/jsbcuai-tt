# 当前录单模板与税价

原流程生成ERP业务单据导入模板：销售订单、商品编号填写、商品名称留空由ERP识别。原型脚本里固定客户、经手人、日期和目录不是通用规则。

本轮用户确认的当前规则优先于旧包：基本单位“支”（空单位由受控程序在已核实base_unit=1时补支）；只有江苏优螺仓库；经手人由本人在每个会话选择李瑄或刘锋，制单人罗健树。模型不得设置或修改这些人员身份。

税率13%，客户报价未明示未税时按含税。服务端使用Decimal及统一舍入：含税价÷1.13→未税单价三位；三位单价×数量→行金额两位。保留原报价，不能使用历史成交价或重复除税。

十段摘要依次为：`客户订单号#项目号#订单行#客户料号#原品名#原标准规格#原等级#原表面#原数量#ERP编码`。当前在尾部追加 `#交期=YYYY-MM-DD`；该摘要进入 API 的单据摘要及明细描述。按用户当前要求，不添加附加说明/comment。核对表中的摘要与实际 API 摘要一致。原订单备注就是如今摘要，不能用comment代替。客户项目号里原有#不能随意吞掉；服务端负责长度、段数和分行规则，模型只提供原始字段。

同编码重复原明细保持独立，交期可逐行不同。单号由受控程序生成唯一编号和本次尝试绑定，不照搬旧脚本 `客户订单号#订单行` 作为全局唯一保证。

确认冻结草稿后，校验人员/仓库/单位、税率、舍入、每行摘要和交期、商品编码及行数；同一冻结模型生成核对 Excel 与 API 参数。只创建未审核销售订单，不自动审核。取得有效单据编号回执后显示已录入；超时、部分成功或未知结果冻结原尝试，禁止自动重传。不运行 N150 网页上传，不做日常销售订单回查。新商品创建仍须回查确认编码及唯一身份。
