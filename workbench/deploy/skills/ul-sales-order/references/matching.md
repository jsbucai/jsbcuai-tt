# NAS匹配资料与核对顺序

原包：`Fastener_AI_N150_20261006-001631`。录单流程原本由 `AGENTS.md`、`04_程序/process_quote_to_sales_import.py`、通用 `match_order_items.py` 以及六份JSON组成，没有独立的录单SKILL.md。本技能把这一套流程迁为N150受限任务入口，而不执行旧Windows上传脚本。

1. 原始字段：客户、订单号、项目、订单行、客户料号/图号、品名、标准/规格、材质/等级、表面、数量、本次报价、交期。原文不改。
2. 普通客户的精确料号历史只在相同客户身份内查询；缺历史时检索当前API商品目录。唯一客户料号命中也要对照明确给出的完整属性。旧客户名/客户码与当前身份冲突不得模糊合并。
3. `客户料号规则.json` 明示达涅利体系及 `0.000452.M` 一类格式可用集团共享料号；必须唯一ERP编码。多个编码显示分布及差异，不能凭最高频决定。
4. `商品名称同义词.json` 的产品族、简称只用于召回；例如“螺母”并不证明是普通六角螺母，“圆柱销”并不排除内螺纹型。标准和结构必须核对。
5. `标准关系规则.json` 区分同编号写法归一、召回组和有限的明确ERP匹配关系。GB/T5781与GB/T5783仅在六角头螺栓、规则启用且证据存在时可提出关系；保留客户原始5781摘要。不由DIN933推定任何GB标准等价。
6. `允许替代关系.json` 的140HV/未指定硬度→200HV，只限碳钢标准平垫圈及列出的标准。特殊材质、倒角、大平垫、非标平垫不能套用；材料证据不足则保留问题。
7. `表面处理同义词.json` 中复合涂层/达克罗可召回，但客户写复合涂层，输出原文仍写复合涂层。附加研磨工艺、特殊热浸锌、现货颜色等风险不能丢弃。

当前API目录的 `standard_no` 是标准来源，等级及表面常在 `model`。受控程序只解析唯一显式token并保留字段出处，不更改inventory；缺失或冲突的token保持待核对。空编号、停用、删除、同编号多有效身份、非江苏优螺仓库及未核实单位不允许自动采用。

历史 `raw_remark` 是当前ERP `summary` 的旧字段名，不是 `comment` 附加说明。历史参考保留原文件哈希、原来源行、真实日期覆盖及解析冲突。历史只提供编码证据，不提供本次价格、数量或交期，也不宣称已补齐当前所有历史。
