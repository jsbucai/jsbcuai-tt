# UL Android independent data service

Start `start-service.ps1` on the workbench computer; the native app uses `http://192.168.1.5:5191/api/v2`. The app factory is `app.create_app()`. `run.py --prepare-only` performs the initial source copy/import without opening a port. Run tests with `.venv/Scripts/python.exe -m pytest tests -q`.

This directory is independent of both existing services. The fresh database is `runtime/data/workbench.sqlite3`; immutable source snapshots are under `runtime/data/snapshots/generations`. No 5190 database was copied. Original input files are restricted to the three approved constants in `core/snapshots.py`: orders, sales validation, inventory. Source files are read-only. Malformed sales XLS exports are recovered only from the newly copied file using a separate invisible Excel instance with links/macros/events/calculation disabled; no source workbook or existing Excel session is changed.

Every 60 seconds, the running service compares source modification time and size with the imported manifest. A change causes a serialized new snapshot and atomic database publication; queries continue against the prior complete version until success. Refresh failure retains current data and appears under `health.monitor.last_error`. Source modification time is reported separately as `source_updated_at` and each source's `source_modified_at`; the app should display those rather than copy time. Repeated source stat checks do not refresh unchanged data.

Print preparation only emits the verified 5088 mobile text/QR CPCL layouts, with GB18030 encoding and preserved standard/spec spacing. There is no PNG/raster fallback, label editor, Windows printer transport, Bluetooth connection, or physical output endpoint. `expected_data_version` ensures selected records belong to the query version; frozen prepared jobs and one-shot claim/result records survive later data refreshes. Sent/accepted never means verified paper output.

Version 0.1.2 adds explicitly submitted ERP inventory adjustment batches. The Android app keeps drafts locally; `POST /api/v2/adjustment-batches` freezes one loss/overflow list in `adjustment_batches` and returns immediately. A single independent worker builds one XLS file and imports it once. `GET /api/v2/adjustment-batches/<id>?client_id=<uuid>` returns durable progress; retry is allowed only after a confirmed pre-submission failure. The frozen batch UUID prevents a lost HTTP response from creating another ERP document. Recovery marks interrupted running work unknown, never queues it again automatically.

Version 0.1.3 adds an explicit manual confirmation endpoint for an owned unknown batch after its ERP document is checked. It records the previous state and user confirmation in `adjustment_confirmations`, marks that batch complete with `completion_source=user_verified`, and never invokes the ERP sender. Interrupted batches recover their display document reference from their own submission marker. Existing unknown rows are not silently cleared during upgrade. The inventory `sku` parameter now matches an exact code; general keyword/name/spec/model searches remain unchanged.

Service 1.2.1 restores the complete 0.1.2 order/inventory CPCL renderer after the user supplied physical A300E labels showing that 0.1.3's reduced text was unreadable. New print preparations use the old sizes, weights and positions; existing frozen jobs are immutable. The Android 0.1.3 APK and all non-layout fixes remain. Desktop substitute-font previews and geometric fit tests do not establish physical legibility; future typography changes require an actual printer sample before replacing this baseline. See `../docs/LABEL_ROLLBACK_2026-09-10.md`.

The ERP adapter reuses the existing ERP login/business-import helpers and the established loss/overflow template mapping, with its own browser profile under `runtime/data/adjustments/session/chrome-profile`. It does not reuse CDP or the old browser profile, modify 5088, or consume 5088 pending rows. A positive fresh import progress receipt with matching row count and a completion marker is required. Data files and authenticated browser state remain local; do not publish the runtime directory. If the first independent ERP login needs intervention, use its login window on this workstation. Physical inventory quantities in the app change only when the ERP inventory export is updated, not optimistically on submission.

See [API_CONTRACT.md](API_CONTRACT.md) for native field mapping and endpoints. This first version trusts devices on the local private network. Requests from public client addresses are rejected; the optional Origin check is an additional browser check, **not authentication**. It has no user identity/authentication or TLS and must not be exposed through public port forwarding or a public reverse proxy. Configure additional authentication before deployment outside the trusted LAN.

The Python virtual environment reuses existing system spreadsheet dependencies without changing them; waitress and pytest are installed in this service's own `.venv`. Service launch checks port 5191 and waits for the expected health response before reporting success. It never stops other processes and does not modify 5088/5190 or the old Android printer helper.

## Reserved integration addresses

Service 1.2.2 reserves `/integrations/wsgjp/callback` and `/integrations/wsgjp/notify` as disabled LAN-only addresses. They return 503 without completing authorization or acknowledging a message. These are registration placeholders, not an active API integration; acceptance by the vendor form is unverified. No credentials are stored, no public exposure is added, and existing business flows are unchanged. The saved addresses and activation requirements are in `../docs/UL随行_管家婆接口预留地址.txt`.

## Windows background operation

Run `install-autostart.ps1` once as the Windows user who uses this workstation. It creates the separate `UL_Android_5191` Task Scheduler entry and starts it immediately. The task runs hidden with limited privileges at that user's logon, without a runtime limit. The supervisor waits for an existing healthy service process to exit and starts it again after five seconds; a named mutex and the task's IgnoreNew setting prevent duplicate supervisors. It never kills a busy or unhealthy process and therefore does not interrupt an active print job to recover a health timeout.

This is user-logon startup, not a system service before login. A powered-off, sleeping or logged-out workstation cannot provide this LAN API. Supervisor errors are in `runtime/watch-service.log`, rotated at 1 MiB with one previous file; server startup errors are in `runtime/server.err.log`.

To remove automatic startup, stop and unregister only `UL_Android_5191` in Windows Task Scheduler. Removing/stopping this task may stop its child 5191 service, so finish active work first. The original `start-service.ps1` remains available for manual operation. This does not remove the database, snapshots or print ledger. No firewall, router, DNS or public deployment settings are changed by these scripts.
