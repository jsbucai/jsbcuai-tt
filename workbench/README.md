# UL 随行 · Android 原生开发版

当前交付为 **0.4.11-dev / code 24**，N150 后端 `0.5.17-codex-summary`。销售录单已接入 NAS 原规则及 N150 Codex，摘要按 App 十段字段并带逐行交期；每条客户明细生成独立 ERP 单据，再统一网页上传。已发布到安装页，保留原签名和业务记录。验证范围、真实操作验收缺口及回退说明见 [0.4.11 发布验证](docs/RELEASE_0.4.11.md)。下文旧版本说明保留供追溯。

Kotlin + Jetpack Compose 原生应用，红 / 白 / 黑配色。0.3.0 起，订单、库存、台账、图片和打印协调使用 N150 公网服务；原电脑的 `192.168.1.5:5191` 只保留局域网报损报溢草稿上传。业务页面不加载 WebView。

当前公网入口是 `https://ul.yingyinghome.com:8443`。N150 只处理 08390 仓库，缓存查询数据、库存流水、图片元数据和打印状态；Android 手机直接连接 A300E。商品详情按需读取最近四次正向入库范围内的实物库存台账及一张 ERP 主图，图片编辑结果只保存为手机副本。

0.3.1 起，WMS `receiveraddress` 按业务约定作为客户／公司名称，订单筛选面板可直接选择当前未发货订单中的客户。该字段为空时保持空值，不使用收件人姓名、电话或账号推测。

0.3.3 起，订单页可直接点选“全部、异常、需采购、待到货、催货、来货件、库存”，库存内保留 LS／LD／LM／DQ／QT 五类。订货日期和交期通过日历点选，筛选和整单打印共用同一查询范围。

0.4.0 起，员工登录后进入“任务”首页。销售、采购、库存件包装和来货件包装事项从同一份已发布订单及分类结果生成；员工账号、岗位、在岗状态、处理记录、转交记录和每日统计保存在 N150。自动派工默认关闭，管理员核对预览、建立人员并设置在岗后再开启。包装任务与整单打印锁共用负责人校验，每名包装员工默认最多保留 3 单；“已打印”“已包装待发货”和 ERP 已确认发货分别记录。

0.4.1 起，销售与包装任务首页按客户订单号第一个 `#` 前的文本汇总为客户整单卡，每页 20 张；点开后查看全部订单行、缺项与关联采购事项。销售只需在整单上记录一次跟进，追加订单行会显示变化提醒。已齐行仍可先包装；只有全部有效未发行齐货、明确包装完成且没有待核对项时才显示“可安排整单发货”。同前缀客户名称缺失或不一致的整单先进入待核对。管理员可在详情中调整整单销售负责人；首次启用自动派工时，预览期已建立但尚未分配的整单也会分配。采购事项仍按商品汇总，并显示受影响整单数及只差此商品的整单数；包装任务仍以完整系统订单号逐行领取并遵守原限额及打印锁。管理员上线前应先核对“待核对”筛选、负责人和订单行，人员维护仍在任务页右上角。

**当前 0.4.2 已替换上述任务页与包装限额：**默认展示本人全部未完成事项，每次 50 项自动续页；销售按客户整单，采购按商品，包装按同品和货位展示。同品包装自动派工不再有 3／10 条数量上限，已开始、历史打印及人工交接过的订单保留负责人。筛选内可看本岗位全部工作，但不能操作其他人的事项。销售采购可批量记录点选结果、承诺与下次日期；包装可对固定的完整选择范围批量开始、分段打印和确认包装。数据仍由手动“更新订单”同步。详见 `docs/RELEASE_0.4.2.md`。

0.3.2 起，奇门 `process_state=500` 的已出库未记账订单显示为“已完成订单需结存”。它们继续占用库存／采购未到 FIFO，避免 ERP 尚未扣减的库存被重复分配，但不会进入包装选择、未打印列表或 A300E 打印。500 和 600 均采用连续确认，短暂接口不一致时显示“订单状态待核对”并保持保守占用。物流公司编码从 ERP 字典读取；历史交期只接受已验证缓存，不拿订货日期猜测。

后端 1.4.5 起，先按账套、08390仓库、商品、SKU和基本单位汇总全部活动需求及已出库未记账的影子需求，再计算净调整量：`净调整 = 可销售库存 - 实物库存 + 全部销售未完成需求`。正数作为采购／改制未到；负数作为 ERP 已计入可售的推算其他占用，并从实物库存扣除后继续 FIFO。它不是简单忽略负数，也不宣称已通过 API 读取到具体草稿单。

## 安装与使用

1. 安装 `releases/current.json` 指向的原签名 APK；覆盖安装会保留服务器、会话、设备 ID 和报损报溢草稿。
2. 打开 **UL 随行**，管理员可继续只填密码登录；员工使用管理员建立的用户名和密码登录。公网地址默认为 `https://ul.yingyinghome.com:8443`。
3. 到“设备”允许附近设备权限，开启蓝牙，查找并连接 A300E。局域网报损报溢上传仅在原电脑服务健康时启用。
4. 回到订单页选“全部 / 库存件”，库存件可继续选 LS / LD / LM / DQ / QT。扫码枪直接输入，无需点输入框。
5. 核对需求、可销售库存、库存数量。订单默认选中本页，可只选某一单；库存仅唯一结果自动选中，多结果请选所需商品，再打印。
6. 发送完成后直接继续扫码。若提示出纸情况未知，先检查标签再点“已核对出纸”，不会自动补打。

支持外接 HID 扫码枪和主动手动查询，未包含相机扫码。与 5088 使用相同功能码：订单页 `PALL01` 等同点击“打印”，`PBOX01` 等同点击“拆箱”，作用于当前选中项；库存页两个码都等同点击“打印”。服务对 100 条记录 / 100 张标签设明确上限，超出时提示缩小范围。

0.1.1 更新：库存手动输入支持名称、规格、等级 / 型号组合查询；“更多条件”可填编号 / 货位关键词和材质。多个非空条件同时匹配，支持部分填写。订单卡片增加原订单型号。订单和库存各自保留本次 App 使用期间的查询、选中项和滚动位置；结果旁点“清空”仅清当前页，重复点击导航不清除结果。切换服务器会清除两页缓存，已更新的数据仍须重新查询核对后才能打印。

0.1.3 更新：库存商品编号放在手动查询第一栏，格式为两位字母加四位数字。小写自动转大写，有效六码立即精确查询；前缀请求英文键盘，后四位请求数字键盘，具体布局由手机输入法决定。名称 / 规格 / 型号的组合查询继续保留。扫码枪的键释放和回车尾码不再误触“停止发送”。设备页的待核对清单可在核实 ERP 后点“已核对，确认入账”，保存人工核对记录并收起该条，不重传 ERP。2026-09-10 收到实际打印反馈后，服务 1.2.1 将订单与库存标签完整恢复到 0.1.2 的原字号、字重与位置；App 无需重装，其他修复继续保留。详见 `docs/LABEL_ROLLBACK_2026-09-10.md`。

“已发送”表示蓝牙传输完成，实际出纸仍须由 A300E 核对。所有自动化都使用模拟设备，不会消耗标签纸。

## 本机构建

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

输出 `app/build/outputs/apk/debug/app-debug.apk`。任务默认包含打包、单元/原生 UI 测试、lint。固定 AGP 8.7.3、Kotlin 2.0.21、Compose BOM 2025.02.00、compile/target SDK 35、最低 Android 8.0，使用现有 JDK 17 与 SDK。版本经过本次实际构建验证后记录到验证文档，不因官方文档示例更新而在日常发包中自动升级。

脚本在项目 `runtime/toolchain` 安装 SHA256 校验过的 Gradle 8.9，不修改旧助手工具。此电脑 Java 直连 Maven 遇到 TLS 故障，构建脚本使用仅监听 `127.0.0.1:5192` 的 Maven 下载缓存，通过 Python 验证 HTTPS 到官方仓库；未关闭上游 TLS 验证。普通开发环境可直接使用 Gradle 与官方仓库，不设置 `UL_MAVEN_BRIDGE` 即可。

Windows JDK 17 的测试进程会受中文路径与系统代码页影响。测试任务仅将生成的测试类路径复制到 Gradle 用户目录的 `ul-workbench-test-classpath`，源文件和正常 APK 输出仍保留在原项目。原生界面截图通过 Robolectric 的 Native Graphics 渲染，不能替代手机键盘、扫码枪和打印机的实际验收。

开发签名固定保存在项目 `runtime/signing`，初次从 Android debug keystore 复制或创建，该目录不提交代码仓库。正式版另行配置发布签名及备份。不要删除签名后重新生成，否则 Android 无法覆盖安装旧包。

验证通过后运行 `python scripts/publish_dev.py`。脚本校验 APK 签名、应用 ID 和 ZIP 完整性，原子替换版本 APK 与 `releases/current.json`；安装页自动加载发行记录，下一次更新不用改下载路由或重启数据服务。

## 当前运行边界

- N150 公网服务负责订单、库存、采购、库存台账、产品主图、更新任务和整单打印状态；所有业务数据只处理 08390 仓库。手机查询读取 N150 的已发布 SQLite 快照，不在每次搜索时等待 ERP。
- “更新订单”由用户手动触发。日常更新复用商品、WMS 订单日期和库存流水水位；库存台账读取最近水位前 72 小时的重叠窗口。每 7 天的完整核对也只在下一次手动更新中执行，没有独立业务定时任务。
- 每次订单数据成功发布后，N150 会基于相同数据版本刷新每日任务；任务刷新失败不会撤销已发布查询数据，任务页会显示版本落后并暂停包装操作。每天只结转本地任务记录，新一天不会自动读取 ERP，也不会依据旧库存追加包装派工。
- ERP 物流写入默认关闭。缺少摘要交期、WMS 唯一明细或其他分类依据时，查询仍可发布，但对应订单保持阻断，不会生成物流请求。
- 报损报溢草稿保存在手机，并固定提交到原电脑局域网服务 `http://192.168.1.5:5191`。局域网不可用时只保存草稿；上传成功表示 ERP 草稿已建立，不表示已经过账。N150 随后只读取受影响商品的 `qty/saleqty`，不人工改写实物库存。
- 产品原图由 N150 代理并按需缓存，手机不接触 ERP 密钥。下载、裁剪、旋转、画笔和马赛克结果只保存为手机副本，不修改 ERP 原图。
- 5088、5190 及原电脑的其他程序不参与 N150 公网服务。SQLite 始终运行在 N150 本地磁盘，NAS 只保存一致性加密备份。
